Thesis

An agent with tools is a credentialed insider.

Give a model a shell, an API key and a goal, and it behaves like a new kind of insider. It is fast, it doesn't tire, and it pursues its objective through paths nobody reviewed in advance. It needs the same scrutiny as any privileged identity, whether or not it ever intends harm.

DarkLab is a non-commercial notebook for my independent research on that problem. It draws on two decades of adversary emulation, detection and incident response.

  1. 01 Emulate Run the attack an agent could plausibly attempt.
  2. 02 Detect Measure whether the monitor actually catches it.
  3. 03 Adjudicate Separate genuine harm from benign-but-unusual.
Focus areas

What I work on.

Four overlapping areas. The common question is what an AI system can do to a defended environment, and what stops it.

EVAL

Cyber capability evaluation

  • LLM-driven offensive assessment harnesses
  • Agent scaffolds and CTF-style benchmarks
  • Grading agent output against real targets
SANDBOX

Agent security

  • Tool-use and MCP trust boundaries
  • Prompt injection into agent workflows
  • Coding-agent permissions and failure modes
CONTROL

AI control & monitoring

  • Trusted monitors for untrusted agents
  • Rules-of-engagement checks for offensive agents
  • Trajectory review and adjudication
ADVERSARIAL

LLM attacks

  • Prompt injection and RAG poisoning
  • Jailbreaks and guardrail bypass
  • LLM output as an injection vector
Foundations
Judging offensive AI capability is easier if you have done the offensive work yourself, against real, defended targets.

Regulatory-tier red teaming

CBEST, TIBER and iCAST adversary emulation against financial institutions. Useful for judging whether model-generated exploitation would work against a hardened target.

Enterprise trust boundaries

Active Directory, SAP, SWIFT and the authentication around them. An agent with tool access raises the same trust-boundary questions.

Detection & adjudication

Detection content, threat hunting and incident command: deciding, under pressure, whether activity is an attack or just unusual.

Practice leadership

Over 20 years leading offensive security teams in banking, consulting and defence: scoping engagements, setting methodology and developing practitioners.
